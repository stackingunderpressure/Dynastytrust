Understanding DynastyTrust vault policy
What is a Dynasty Vault?
A DynastyTrust vault is a Bitcoin address governed by a Miniscript policy compiled to either Taproot (recommended) or SegWit v0. The policy encodes three spending paths with different conditions:
or( thresh(FOUNDER_QUORUM, pk(founder1), pk(founder2), ...), -- Founders now or( and(after(RECOVERY_BLOCKS), thresh(FOUNDER_QUORUM, ...)), -- Founder recovery and(after(INHERITANCE_BLOCKS), thresh(HEIR_QUORUM, ...)) -- Heir inheritance ) )
This gives founders immediate control, a timelocked recovery path (in case of hardware failure), and an inheritance path that activates after a long delay.

NUMS Internal Key
All Taproot vaults use a provably unspendable internal key (NUMS — Nothing Up My Sleeve point). This means the keypath spend is impossible, and all spending must go through the Miniscript script path. This is the recommended practice for multisig Taproot vaults and makes the policy auditable.

Importing into Sparrow / Nunchuk
The output descriptor from a compiled vault can be imported into Sparrow Wallet or Nunchuk as a watch-only wallet. This allows you to monitor the vault balance and prepare PSBTs for signing with hardware devices (Coldcard, Trezor, Ledger).
  1. Copy the descriptor from your vault detail page.
  2. In Sparrow: File → Import Wallet → Descriptor.
  3. In Nunchuk: Create Wallet → Import from Descriptor.
  4. Connect your hardware signer to generate the PSBT.
